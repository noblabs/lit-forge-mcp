# 地政学イベント・リアルタイム化設計（v0.9.0）

## 背景

v0.8.0 の `get_geopolitical_events` は手動キュレーション JSON（半年に 1 回 PR で更新）を返す設計だった。
2026-05-14 のユーザーフィードバックで以下が判明:

- 「トランプ・習 北京会談（5/14）」「イラン情勢」「ウクライナ和平」など、市場を動かす突発・進行中イベントが**設計上ヒットしない**
- 半年更新サイクルは原理的にリアルタイム要件を満たせない
- 「確定済み公式日程のみ」「主観判断要件は登録禁止」の中立性ガイドラインが、結果として**最も役立つ情報の除外**を招いた

カレンダーアプリとリスクセンサーは別物。1 ツールに混在させていたのが構造的な問題。

## 設計原則

1. **2 ツールへ分離**: 確定スケジュール (calendar) と速報 (pulse)
2. **客観性の基盤を再定義**:
   - calendar: 引き続き「確定済み公式日程のみ」（中立性ガイドライン継承）
   - pulse: 「**主要通信社が編集判断のうえ報道した記事のメタデータ**」を客観性の根拠とする
3. **解釈責務は LLM 側**: ツール出力には主観的な marketImplications を含めず、客観事実（タイトル・配信日時・配信元）のみ返す。LLM が市況サマリーを書くときに自分で解釈する
4. **ゼロ運用コスト維持**: 認証不要・APIキー不要・サーバー無し

## アーキテクチャ決定

### データソース選定（PoC 結果）

| 候補 | 結果 | 採否 |
|---|---|---|
| **GDELT Doc 2.0 API** | レート制限が厳しく（~5s/req）連続実行で fetch failed、タイムアウト多発 | ❌ v0.9.0 では見送り |
| **GDELT Events 2.0 CSV** | 機械符号化済み CAMEO データだが zip 解凍依存 + 15 分窓で 3 万件規模のパース必要 | ❌ 複雑性過剰 |
| **主要通信社 RSS（BBC・Al Jazeera・Google News）** | 100-700ms で 25-100 件取得、Trump-Xi 会談記事を即ヒット | ✅ 採用 |
| Reuters / AP / NHK RSS | 全て 404 / フィード仕様変更で取得不可 | ❌ |

### 採用アーキテクチャ

```
                                                     ┌─────────────────┐
                                                ┌──→│ BBC World RSS   │
                                                │   └─────────────────┘
                                                │   ┌─────────────────┐
[MCP request]                                   ├──→│ Al Jazeera RSS  │
   │                                            │   └─────────────────┘
   ▼                                            │   ┌─────────────────┐
get_geopolitical_pulse({topic, maxItems})  ─────┼──→│ Google News RSS │
   │                                            │   │ (topic query)   │
   │   並列フェッチ + 正規表現で minimal XML パース  │   └─────────────────┘
   │   ↓                                        │   ┌─────────────────┐
   │   タイトル類似度で dedupe                    └──→│ (拡張余地)       │
   │   ↓                                            └─────────────────┘
   │   pubDate ソート（新しい順）
   │   ↓
   └─→ JSON 返却（title / source / pubDate / url / topic）
```

### ツール仕様

#### `get_geopolitical_pulse`（新規）

- 用途: 今この瞬間の地政学関連ニュース（突発・進行中）
- 入力:
  - `topic`: `us-china` / `middle-east` / `ukraine` / `japan` / `global` から 1 件選択（既定 `global`）
  - `maxItems`: 5-30、既定 15
  - `hoursBack`: 6-48、既定 24（これ以上古い記事は除外）
- 出力: 記事メタデータの配列（タイトル・配信元・配信日時・URL）+ 取得元 RSS リスト + 注記
- フェイルセーフ: 1 フィード失敗時も他フィードの結果を返す（部分成功）
- キャッシュ: プロセス内メモリで 15 分 TTL（同一プロセス内で複数ツール呼び出しがあるケース向け）

#### `get_geopolitical_calendar`（リネーム: 旧 `get_geopolitical_events`）

- 用途: 確定済み公式スケジュール（G20・選挙・確定済み首脳会談・条約期限）
- 既存実装をそのまま継承。description のみ「確定スケジュール専用」と明文化
- 後方互換: 旧名 `get_geopolitical_events` は v0.9.x で deprecation 警告付き残存、v0.10.0 で削除

### 中立性ガイドラインの更新

旧（v0.8.0）:
> 確定済み公式日程のみ収録し、主観判断を要するイベント（紛争激化等）は登録しない

新（v0.9.0）:
> **calendar 側**: 旧ルールを継承（確定済み公式日程のみ）。
> **pulse 側**: 主要通信社が**編集判断のうえ配信した記事のメタデータ**を客観性の基盤とする。
> ツール出力には主観評価を含めず、解釈は LLM 側の責務とする。

これにより「確定日程しか出ない不便さ」と「主観混入による信頼性低下」を両立解決する。

## 実装方針メモ

- **依存追加なし**: RSS は正規表現 (`<item>` / `<entry>` 抽出 + CDATA 剥離) で十分。将来 fast-xml-parser に切り替え可
- **タイムアウト**: 各 RSS フェッチに 10s。複数フィード並列なので合計 12-15s 上限
- **dedupe**: タイトルを小文字化 + 記号除去 + 先頭 60 文字でハッシュ比較
- **エラー透過**: 個別フィード失敗は`sources` 配列に `error` フィールドで返す（呼び出し側で部分結果を判断可能）
